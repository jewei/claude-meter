## Networking — `ProviderHTTP.swift`

- **All** provider HTTP goes through `ProviderHTTPClient.shared` (a `HTTPTransport`): one cookie-less ephemeral session with a 10 s idle timeout and a 30 s hard whole-send deadline, including retry waits. `ProviderHTTPSessionDelegate` receives data in chunks and retains at most 8 MiB (the models.dev catalog is already larger than 4 MiB); it rejects a larger declared `Content-Length` before body receipt and cancels on streamed overflow. The hard deadline uses a dedicated bounded `Timeout.TaskBudget`, so a cancellation-ignoring URL task cannot hold its caller or create unbounded abandoned work. The delegate also applies `RedirectGuardDelegate`'s same-origin HTTPS rule — credentials (`Bearer`/`Cookie`) must never be replayed off-origin or downgraded. OAuth and status clients all use it.
- `HTTPRetryPolicy` (`.none` / `.transient`) gives bounded retries (idempotent methods only, honors `Retry-After`, exp backoff capped at 8 s). `.transient` excludes 429 (OAuth handles its own backoff) and also retries selected `URLError` timeouts. status GETs use `.transient`; OAuth keeps its own provider-wide 429 `rateLimitGate` and uses `.none`.
- **Inject a stub `HTTPTransport`** to unit-test a client without network (see `AnthropicStatusClient(transport:)` and `TransportInjectionTests`).

## Keychain reads

- **Settings preflight never reads secrets** — `OAuthKeychain.credentialAvailability()` performs an attributes-only lookup. The first `loadResult()` is behind the user's confirmed Connect action. Existing-user onboarding detection counts only `.available`; `.temporarilyUnavailable` is not proof that an item exists. All `SecItem*` calls in the app go through `KeychainGateway` (`KeychainGateway.swift`) — the one fail-closed, no-UI boundary, shared by `OAuthKeychain` and `CursorTokenStore`; test processes receive `errSecInteractionNotAllowed` unless `CLAUDE_METER_ALLOW_LIVE_KEYCHAIN_TESTS=1` is set explicitly. **The test detection is a dyld image scan** (`testFrameworkIsLoaded` — is `XCTest`/`Testing.framework` linked?), because every launch-shaped heuristic misses `swift test`: swift-testing runs in a shared toolchain helper (`swiftpm-testing-helper`) whose process name, `Bundle.main`, and argv[0] have nothing to do with a `.xctest` bundle. That gap silently opened the gate — the whole suite was reading the real login Keychain — so don't "simplify" the check back to a process-name test.
- `OAuthKeychain.loadResult()` / `loadManualResult()` return `KeychainReadResult { found / missing / temporarilyUnavailable / invalid }`; `mapKeychainStatus` classifies the `OSStatus` (a locked Keychain → `temporarilyUnavailable`, `errSecAuthFailed` → `invalid`, never `missing` on error). `OAuthPipeline.poll` and `fetchEnrichment` branch on these (prefer in-memory cache on `.temporarilyUnavailable`). `load()`/`loadManual()` remain the `Optional` convenience wrappers.
- **Hashed service-name fallback** — Claude Code ≈2.1.52+ namespaces the credentials entry per install/config dir as `Claude Code-credentials-<hash>` (a machine can hold several + the legacy unsuffixed one). `readClaudeCodeCredentials` reads the legacy `Claude Code-credentials` first; **only** a genuine `.missing` (not a lock, not a present entry) falls through to `discoverHashedServiceName`, which enumerates generic-password **attributes only** (`kSecReturnAttributes`, no `kSecReturnData` → no Allow/Deny prompt, no `security` subprocess) for `NSUserName()` and reads the entry with the newest `kSecAttrModificationDate` (the live login). Selection logic is the pure, tested `newestHashedService(among:)`. No `dump-keychain` (the reference app's approach — slow/hang-prone; unneeded via Security.framework).

## Local provider files

- **Reads must reject blocking special files and unbounded sizes** — use `BoundedRegularFileReader` for auth, settings, identity, event, and advisory-cache JSON. It opens with `O_NONBLOCK`, accepts only a regular file after `fstat`, caps allocation, and reads through the descriptor. Auth/settings/identity/cache paths may follow a symlink because users can deliberately link those files; app-owned statusline payloads and event markers reject links, including linked account directories. Open the app-owned `.claude-meter` root first, then traverse with `openat`; final-component `O_NOFOLLOW` does not reject a linked parent. Destructive cleanup must unlink only an unchanged entry through the descriptor that inspected it, and it can leave empty managed directories. Do not replace this boundary with `Data(contentsOf:)`: a FIFO can retain a timeout worker forever because task cancellation cannot stop a blocking filesystem call.

## Statusline bridge

`StatuslineBridge.install(configDirs:)` runs on launch and each poll while statusline is enabled (idempotent + self-healing). `refreshConfigBridges` removes the snippet from disabled accounts. When the source is **off**, it removes the snippet from all discovered accounts and calls `purgeSessionData()` if any valid file changed, including when another account has invalid JSON. The purge is separate so `uninstall` never touches `~/.claude-meter` from tests, matching `HookBridge`. The bridge prepends a bash snippet to each enabled config dir's `settings.json` `statusLine.command`. It derives the **account key** from `$CLAUDE_CONFIG_DIR` (basename, one leading dot stripped, sanitized to `[alnum._-]`, fallback `claude`), extracts `session_id` (same sanitization), atomically writes stdin to `sessions/<accountKey>/<session_id>.json`, and sets `refreshInterval: 1`. The no-arg `install()`/`uninstall()` are `~/.claude`-only shims. A dir with invalid JSON is skipped, its error is surfaced after all other dirs are processed.

- **Multi-account is the whole point** — power users run several Claude accounts via `CLAUDE_CONFIG_DIR=~/.claude-x claude`. Rate limits are **per account**, so the bridge tags each window's files by account and the app never blends them. `ConfigDirDiscovery` is the single source of truth for the account key/label and **must stay byte-identical to the bash snippet** (explicit ASCII allow-set, *not* Unicode `Character.isLetter`). The payload JSON carries no org/email, so the config dir is the only stable identity the *bridge* has; the multi-account OAuth tier adds per-account org/email from `.claude.json` + the usage response header. `OAuthPipeline` (top-level tier + enrichment) stays single-slot for the **active** account; `MultiAccountOAuth` covers the rest.
- **Per-account grouping + merge** — `readDataGrouped(maxAge:)` buckets fresh `*.json` by account subdir (legacy flat files + the legacy `statusline.json` → default `claude`) and runs `mergePayloads` **within each account only** — never across, since rate-limit buckets are independent: five-hour and weekly both use **max `resets_at`** (most recent observation). `StatuslinePipeline` mirrors the **active account** into the snapshot's top-level fields and lists the rest in `ClaudeUsageSnapshot.accounts` (nil only for a lone *default* `claude` account → `current.json` byte-identical to before; a lone *non-default* account is surfaced as a single-element list so the popover can key per-account name/plan overrides by account key). When Claude is the main meter, primary surfaces use its exact account pin or nearest-limit policy; the top-level active account remains a compatibility mirror. `readData(maxAge:)` is a back-compat shim returning the active account's merged payload.
- **Active-account selection** (`selectActive`/`activitySignature`) — the active account is the one **most recently used**, detected by diffing each account's *activity signature* across polls. The signature is `StatuslinePayload.activityFingerprint` (every session file's `session_id` + `total_cost_usd` / `total_api_duration_ms` / code-lines, sorted) plus the merged used %. **Take it from the fingerprint, not the merged payload's own cost/duration/line fields** — those come from whichever file `mergePayloads` saw last, and with two concurrent windows on one account that flips every poll, which made an idle multi-window account look perpetually active and permanently outrank the one in use. the account whose signature changed most recently wins, idle accounts freeze their last-active time. **Don't use file mtime or `resets_at`**: the bridge rewrites every session file once a second (`refreshInterval: 1`) so idle-but-open looks fresh, and `resets_at` marks when a window *started*, not recent use (this caused an idle account with a later window to wrongly win). Exact ties (cold start / pipeline rebuild, where every account is freshly seeded) fall back to a **sticky** key (the previous active, seeded at init from the last snapshot's `accounts[].isActive` so a relaunch keeps the right account), then window-reset recency (`payloadRecency`), then key order. Switch granularity is one poll (≤60 s) on the menu bar; opening the popover calls `refreshNow` for an immediate re-select.
- **Discovery** — `ConfigDirDiscovery.discover` scans `~/.claude*` (dirs with `settings.json` or `projects/`, always including `~/.claude`) ∪ `AppGroupConfig.configuredConfigDirs`, minus `disabledAccountKeys` (the default `claude` is never disablable), deduped by resolved path + account key. Two **independent** off-main consumers run it each poll: `AppState.scanCostModels` (so the cost union is correct from the first poll, even with the statusline source off) and bridge reconciliation. Reconciliation keeps one active task and one coalesced rerun; it never cancel-and-await chains synchronous filesystem work. Settings → Statusline Bridge card lists discovered accounts (toggle + add-custom-path, validated via `isPlausibleConfigDir`); changes call `scheduleRebuildPipeline()`.
- **Disabling filters the read path too** — `disabledAccountKeys` gates installation, the cost union, and `StatuslinePipeline.eligibleGroups` (injected at `makePipeline` construction, never dropping `claude`). `DisabledClaudeAccountFilteringPipeline` also encloses the assembled chain, so the OAuth-to-cache path cannot restore a disabled account when statusline is off. Reconciliation also removes old bridge and attention-hook snippets from disabled accounts. Read-time filtering stays required because cached files and a bridge process that was already running can continue to exist after removal.
- **Migration / self-repair** — `installOne()` strips _all_ leading bridge snippets (current + `legacyBridgeSnippets`, which now includes the pre-account per-session snippet) via `strippedOfAnyBridge` (loops to collapse chains) before prepending once. Until Claude Code re-runs the statusline, pre-existing flat `sessions/*.json` age out by the 60 s window (no active file move).
- **Snippet quoting** — `session_id` is pulled with `sed -n "s/.*\"session_id\":\"\([^\"]*\)\".*/\1/p"`; the account key with `A=$(basename "${CLAUDE_CONFIG_DIR:-$HOME/.claude}");A=${A#.};…|tr -cd "[:alnum:]._-"`. Keeping `sed`/`tr` in double quotes avoids escaping single quotes inside the outer `bash -c '…'`. Verify byte-exactness via the install round-trip test (the raw `#"…"#` snippet survives JSON encode/decode). Empty/missing id → `default.json`; empty account → `claude`.
- **Pipe order** — bridge must be _prepended_ (`bridge | userCmd`) and must `printf "%s" "$I"` stdin through so the user's statusline still renders.
- **`rate_limits` may be absent** — only present for Claude.ai subscribers after the first API response; `StatuslinePipeline` requires `five_hour` or `seven_day` before accepting bridge data.
- **Parser version** `statusline-1.0`; diagnostics mode check is `hasPrefix("statusline")`.

## OAuth usage API (Claude Code token)

- **Keychain** — `OAuthKeychain` uses Security.framework (`SecItem*`); service `Claude Code-credentials`, account `NSUserName()`. Auto creds vs app-owned manual creds (service `com.jewei.claudemeter-oauth`, account `oauthManual`).
- **`oauthMode` gate** — `OAuthPipeline` only calls the API when `oauthMode` is `auto` or `manual` (`AppGroupConfig.oauthModeKey`); empty skips to tier 3. Manual disconnect deletes the app-owned entry and clears `oauthMode`.
- **Disconnect revokes refresh leases** — cache, manual Keychain deletion, mode clearing, and refresh-generation invalidation share one lock. A token request can finish after disconnect, but it must not commit its rotated credentials or stale refresh-gate state. Settings verification is also generation-guarded and must never re-enable a source that the user disabled while verification was suspended.
- **Auto refresh is in-memory only** — refreshed auto tokens are cached in `OAuthPipeline` for the session; we do **not** write back to Claude Code's Keychain entry. Each cache entry retains the Keychain refresh-token lineage that produced it. A same-lineage rotated chain wins even when its access-token expiry is earlier; a newly observed Keychain token invalidates the old generation and wins regardless of expiry. Concurrent refresh callers share one request. Its result stays in a bounded, generation-keyed handoff after adoption, so a caller that selected the old token before the commit cannot submit that consumed token later. A new source generation cannot reuse the old handoff. **Every current-generation refresh-failure path must clear that cache**; an older generation must not clear or replace a new login. `MultiAccountOAuth` never refreshes (it skips expired creds), so it has no equivalent path.
- **Decode `UsageResponse`, not `[String: QuotaEntry]`** — the endpoint returns extra keys (`limits`, `spend`, `extra_usage`, nulls). `utilization` is already 0–100; don't ×100. `QuotaEntry.utilization` is optional so null/empty windows degrade to "unknown" instead of failing the whole decode.
- **Windows mapped** — `five_hour` → session, `seven_day` → `currentWeekAllModels`, `seven_day_opus` → `currentWeekOpus` (often the binding limit for Max), `extra_usage` → `ExtraUsage` (monthly overage $). All feed severity + notifications (`weeklyOpus` scope). Any **other** `seven_day_<scope>` key (`seven_day_sonnet`, `seven_day_cowork`, …) decodes into `LimitInfo.scopedWeekly` (`ScopedLimitWindow`, dynamic-key decode in `UsageResponse`; null-utilization scopes dropped) and is layered by enrichment like Opus — **display-only**: popover rows below Opus for the active account, never severity/menu-bar/notifications/widget. The statusline parser reads `seven_day_opus` if present, but Claude Code's statusline does not currently emit it — OAuth is the only live source of the Opus weekly window.
- **`limits[]` is the migration path for scoped windows** — model-scoped weeklies are moving from flat `seven_day_<model>` fields into the generic `limits` array (`{kind:"weekly_scoped", percent, resets_at, scope.model.display_name}`; `percent` is percent *used*, same scale as `utilization`). `UsageResponse.init` folds those entries into the **same `seven_day_<model>` keys** — key = first word of the display name lowercased, so "Opus 4.5" → `seven_day_opus` — which is why nothing downstream (`opusWindow`, `scopedWindows`, enrichment) knows which form the server used. **Flat fields always win; `limits` only fills gaps**, so today's path can't regress. `session`/`weekly_all` kinds are skipped (they mirror `five_hour`/`seven_day`); extend `scopedEntriesFromLimits` if those flat fields ever go null too. `OAuthEnrichment?` deliberately has two levels of absence: outer `nil` means the fetch was unavailable/failed and the cached observation may stay; a non-nil enrichment is a **complete successful observation**, so nil Opus/scoped/extra/plan fields explicitly clear stale values. `MultiAccountOAuth.merge` selects the newest complete active-account OAuth bundle before final persistence. Never turn either step back into a fill-only patch — a nulled server limit must disappear from severity, menu bar, notifications, and widget.
- **Statusline can't see Opus/extra/plan** — Claude Code's statusline `rate_limits` only emits `five_hour` + `seven_day`. `seven_day_opus`, `extra_usage`, and `subscriptionType` exist **only** in the OAuth response. `OAuthPipeline.fetchEnrichmentResult` fetches them and retains a typed failure reason; `AppState.oauthEnrichment` layers successful or cached values onto a non-OAuth snapshot (gated on `oauthMode` being set). Its dedicated `ReadingState` is `current` / `stale` / `failed`: a failed refresh keeps the last successful observation timestamp and marks only the OAuth details stale (popover + Diagnostics), never the fresh statusline session/weekly data. Cached Opus/scoped windows become unknown when their reset passes; the pre-reset observation cannot describe post-reset use. The optional `fetchEnrichment` remains a convenience wrapper. `extra_usage` amounts are integer **minor units** (`used_credits`/`monthly_limit` ÷ `10^decimal_places`), not dollars; `is_enabled:false` can coexist with real `used_credits` (e.g. `out_of_credits`).
- **Credential problems are surfaced, not swallowed** — every OAuth failure falls through to the next tier, so a dead sign-in used to look like numbers quietly not moving. `OAuthCredentialIssue.from(sourceAttempts:)` (Core, pure) classifies the OAuth step of a poll into `signedOut` / `signInExpired` / `corrupt` / `keychainLocked` / `retrying`, and `needsUserAction` picks the tone. Rendered by the popover banner and the Settings → OAuth row (which is otherwise stuck on whatever state the user connected with). `notConnected` / `sourceDisabled` / network reasons deliberately map to `nil` — the user either chose them or they clear within a poll or two. **`rateLimited` is the exception**: it maps to `.rateLimited` (informational tone, `needsUserAction == false`) because a 429 can carry an hour-long `Retry-After`, and an hour of frozen numbers with no explanation reads as a broken app. Its countdown comes from `OAuthPipeline.rateLimitedUntil()` (non-mutating, unlike `isRateLimited`) via `AppState.oauthRetryAt`, phrased with `ResetPhrase`; `displayText` is a **method** (`displayText(retryAt:now:)`), not a property. Copy lives on the enum (`displayText`) so both surfaces stay identical; every actionable case says `claude login`, because a rejected refresh token can only be replaced by Claude Code writing a new one — disconnecting in Settings clears our cache but not the Keychain entry.
- **Deferred refreshes report *why*** — `OAuthRefreshGate.availability` distinguishes `tokenRejected` (dead token, needs re-auth) from `backingOff` (transient), and `deferredReason` maps them to `.refreshRejected` / `.refreshDeferred` so the notice can't tell a signed-out user to sit and wait.
- **Persistent usage backoff** — normal app startup enables standard-defaults storage before provider work. The versioned record contains only the observation time and deadline, never credentials. Loading never extends it. Reject invalid/expired records and clock changes that imply more than 24 hours remaining. Hosted tests skip live persistence through the loaded-test-framework check; gate tests use isolated stores. Account or interactive changes never bypass this gate.
- **429 backoff** — `OAuthPipeline` honors `Retry-After` (delta-seconds or HTTP-date) via the provider-wide `OAuthSharedState.rateLimitGate` shared by `poll` and `fetchEnrichment`; while blocked both skip the API and serve the fallback (default 60 s). A valid delay is capped at a **24-hour safety maximum** so an invalid server value cannot disable OAuth for the lifetime of a long-running app; a later 429 can renew the block. `recordRateLimit` **never shortens an active block** — a later 429 with no header must not undo a longer `Retry-After` already honored. `Retry-After` has one parser for the whole module, `HTTPRetryPolicy.retryAfterSeconds` (delta-seconds or HTTP-date); `OAuthPipeline.retryAfterDate` delegates to it. It returns `nil` for a **non-positive** value (literal `0`, negative, past HTTP-date) — the usage API has been seen answering a 429 with `Retry-After: 0` while still refusing, and taking that literally sets `blockedUntil = now`, which `isRateLimited` clears on sight and so disables the gate entirely (it also makes `HTTPRetryPolicy.delay` return 0, i.e. a tight retry loop). `nil` is what makes callers fall back to the 60 s default / exponential backoff — don't "helpfully" reintroduce a `>= 0` guard at a call site. Token refresh preserves `subscriptionType`. Sends `User-Agent: claude-code/<ver>`.
- **`expiresAt` is integer milliseconds** in the Keychain JSON; parse via `NSNumber`/`Int`/`Double`. Refresh when within 60 s of expiry.
- **Token refresh** — `POST https://console.anthropic.com/v1/oauth/token`, `grant_type=refresh_token`, client id `9d1c250a-e61b-44d9-88ed-5944d1962f5e`; usage calls send `anthropic-beta: oauth-2025-04-20`. Empty returned token strings are rejected. Untrusted `expires_in` is clamped to 5 minutes...7 days so a rotated chain is retained without creating an unsafe `Date` or a refresh loop inside the 60-second expiry buffer. It uses the shared transport limits above.
- **Multi-account OAuth tier** (`MultiAccountOAuth`) — per-account live usage without any open CLI session. Claude Code ≈2.1.52+ namespaces the Keychain entry **per config dir** as `Claude Code-credentials-<first 8 hex of SHA-256(config dir absolute path)>` (verified empirically; legacy unsuffixed entry for `~/.claude` — `OAuthKeychain.credentialServices(forConfigDirPath:isDefault:)` tries legacy first for the default dir). Identity (email/orgUuid/orgName/`organizationRateLimitTier`, e.g. `default_claude_max_5x` → "Max 5x") comes from **local** `<configDir>/.claude.json` — for the default dir the file is at the **home root** `~/.claude.json`, not inside `~/.claude/` (`AccountIdentityReader`). `AppState.accountReadings` is gated on **`oauthMode == "auto"`** (explicitly connected — not just the source toggle, and not `manual`): reading another app's Keychain items surfaces the macOS **ACL password prompt once per entry** (the no-UI policy suppresses LocalAuthentication UI but *not* the legacy ACL dialog — a pending prompt blocks the read until the user answers; "Always Allow" persists, plain "Allow" re-prompts next launch). It fetches all discovered accounts every 300 s (shared with the enrichment cadence, off-main, 30 s timeout) and `MultiAccountOAuth.merge` normally fills missing account fields: statusline wins on live session/weekly windows and active-account selection; OAuth contributes Opus/extra/plan/email/org and whole accounts with no live session. For the active account, direct/single-slot and per-account plan/Opus/scoped/extra fields form complete timestamped bundles: the newest bundle replaces both top-level and active-account fields, including nil, and a same-timestamp per-account result wins because that request runs later. A same-account OAuth window fetched after a statusline reset can replace the inferred post-reset zero. If an accounts-nil default snapshot gains only a secondary OAuth reading, the merge materializes the default account as active; the secondary account cannot repair its top-level limits. A lone default account keeps `accounts == nil` (`current.json` byte-compat). **No per-account token refresh** (deliberate): an expired secondary token degrades that account to statusline-only until Claude Code refreshes it locally; the active account keeps full refresh via `OAuthPipeline`. A 429 aborts the remaining accounts via the shared `OAuthSharedState` gate. The response's `anthropic-organization-id` header (fallback: `.claude.json` orgUuid) fills `AccountInfo.organization`; `MultiAccountOAuth.duplicateOrgAccountKeys` flags two config dirs on the same login (popover "same login" badge — one quota shown twice).
- **Partial multi-account refreshes keep last-good data** — successful accounts replace their cached readings; failed enabled accounts retain their prior readings. Before a retained reading is merged, each rolling window whose reset passed after that observation is cleared to unknown. Do not convert it to 0%: the old observation cannot describe use in the new window.

> **Removed (2026-06-29):** the claude.ai web source (`ClaudeAIPipeline`/`ClaudeAIUsageClient`/`ClaudeAIKeychain`/`BrowserCookieImporter`/`CredentialValidator`) was dropped. It set only session / weekly-all-models / weekly-Opus; its sole unique value over the statusline was covering web-only users (who never run the CLI), at the cost of the app's most fragile, privacy-invasive surface (browser-cookie AES decryption). It **never** sourced plan or extra-usage — plan is primarily the **manual per-account picker** (`AppGroupConfig.accountPlans`, Settings) with OAuth's Keychain `subscriptionType` only as an active-account hint; extra-usage is OAuth-only. ## Codex usage (opt-in)

- **Multiple accounts** use one explicit `CODEX_HOME` per account. The ambient
  `CODEX_HOME` (or `~/.codex`) is implicit; Settings stores additional homes by
  canonical resolved path and never scans `~/.codex*` because Codex defines no
  sibling-home naming contract. Settings stores per-path display names; Codex
  cards deliberately hide email. Each home gets its own provider/App Server
  process and OAuth read. Accounts run in batches of three under one 60-second
  provider-wide deadline and an isolated timeout-task budget; a failed account
  retains its last reading while healthy accounts update. The app persists each
  home's last-good reading in standard defaults with account email stripped, so an
  offline relaunch still has an honest observation + age. Latest-attempt time/error
  stay separate from last-success time; a failed refresh does not by itself make a
  recent observation age-stale. Popover and diagnostics render per-account state.
  When explicitly selected as the main meter, Codex owns the menu bar, widget,
  hero, and quota notifications; otherwise it remains secondary.
- **models.dev cache is untrusted** — cached catalogs require a non-future timestamp
  and positive, bounded input/output/cache-read/cache-write/derived-1h rates before
  an exact-model override can replace the reviewed family fallback.
- **Provider subprocess env is scrubbed** — `codex app-server` spawns strip `AuthEnv.overrideVariables` (`CODEX_API_KEY`, `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `ANTHROPIC_*`, Bedrock/Vertex selectors, …) so an env inherited from a terminal launch can't point the read at a different account/provider. Reuse `AuthEnv.scrubbed` for any future provider subprocess.
- **Provider subprocess output is bounded** — `BoundedProcessOutputCapture` caps whole-output commands and `BoundedProcessLineBuffer` caps unterminated protocol lines at 1 MB. Cursor's `sqlite3` keeps draining after overflow to avoid pipe deadlock but rejects the result; Codex app-server also bounds its `AsyncStream` backlog. Never parse a truncated credential or JSON response.
- **Auto fallback diagnostics** — app-server remains preferred, but if it and direct OAuth both fail, `CodexUsageError.allSourcesFailed` retains both sanitized-at-the-app-boundary descriptions. Do not collapse this back to the preferred error; the second reason distinguishes a broken CLI from a missing/expired fallback.
- **Authentication mode** — `account/read.account.type` is retained on `CodexUsage.authMode`; direct OAuth is `.chatGPT`. A successful limits read can still have `nil` auth mode when the advisory account read fails.
- **Windows** — the positional `primary`/`secondary` pair wins; when both are absent, `rateLimitsByLimitId` (camel or snake case) is bucketed by `windowDurationMins` (≤ 24 h → session-like, longer → weekly-like; unknown duration counts as session-like), most-used window per bucket wins, and the limit id becomes the card label. Codex display honors the shared `left`/`used` progression setting; severity always receives `usedPercent`.
- **Codex optional metadata** — custom outer response decoders isolate malformed credit/reset/plan fields from quota data. Invalid values stay unknown. A valid reset count survives malformed detail rows. Keep direct OAuth quota decoding strict.
- **Reset credits** — `account/rateLimits/read` can return `rateLimitResetCredits`; `availableCount` is authoritative because `credits` may be nil or capped. Codex ring cards show that count and all returned title/expiry rows; bar cards and the secondary Codex summary reveal rows when expanded. Missing detail rows do not imply zero available resets. This is display-only; Claude Meter never calls `account/rateLimitResetCredit/consume`.
- **Plan labels** — app-server `prolite` displays as `Pro 5X`; `pro` displays as `Pro 20X`. `go` and `plus` display as `Go` and `Plus`.

## Grok usage (opt-in)

- **Separate from Claude pipeline** — `grokSourceEnabled` defaults `false`; polled in parallel via `pollGrok`, not part of `makePipeline()`.
- **Token read-only** — `GrokAuthStore` reads `~/.grok/auth.json` (`GROK_HOME` override), prefers the `https://auth.x.ai::<client-id>` OIDC entry over legacy `https://accounts.x.ai/sign-in`. Never refreshes, never writes; expired token (~6 h TTL, CLI-owned refresh) → `loginRequired`, never sent.
- **API** — unofficial `GET https://cli-chat-proxy.grok.com/v1/billing?format=credits` (same upstream call as the CLI's `/usage`); may break without notice. `creditUsagePercent` is authoritative; **proto3 omits zero fields** — absent percent with a present `currentPeriod` decodes as 0, not missing. Timestamps carry microsecond fractions — `GrokTimestamp.parse` strips the fraction (`ISO8601DateFormatter.withFractionalSeconds` requires exactly 3 digits).
- **Monetary `{val}` wrappers are minor units** (cents): `onDemandUsed`/`onDemandCap`/`prepaidBalance`.
- **UX** — `grokError` surfaces in popover/settings/diagnostics. Its bar honors the shared `left`/`used` progression setting while severity always receives `usedPercent`. Grok is secondary-only and never drives the selected Claude/Codex menu bar, widget, or quota notifications.

## Cursor usage (opt-in)

- **Separate from Claude pipeline** — `cursorSourceEnabled` defaults `false`; polled in parallel via `pollCursor`, not part of `makePipeline()`.
- **Token read-only** — `CursorTokenStore` reads `~/Library/Application Support/Cursor/User/globalStorage/state.vscdb` (batched `sqlite3 -readonly`, 10 s timeout) with Keychain fallback (`cursor-access-token` / `cursor-refresh-token`) read through `KeychainGateway` — Security.framework under the no-UI policy, **never** `security find-generic-password -w` (that's a secret read that can raise the legacy ACL prompt and bypasses the fail-closed test gateway). `detect()` is memoized against regular-file identities for the state DB, WAL, and SHM at both alias and resolved paths, including sidecar creation/removal. The SHM identity reads the first 96 bytes because SQLite changes its two WAL-index headers through mmap without a reliable mtime or size change. A short or unstable regular SHM disables memoization but still lets bounded SQLite rebuild the recoverable index; a non-regular or metadata-inaccessible path blocks the SQLite read. The complete identity must also stay unchanged across detection before a result is stored. A result that consults either Keychain fallback is never memoized because Keychain changes have no file identity. Never writes back.
- **API** — unofficial Connect-RPC on `api2.cursor.sh` (`GetCurrentPeriodUsage`); may break without notice. `totalPercentUsed` is authoritative over raw spend/limit; the popover also shows the optional `autoPercentUsed` (`Auto + Composer`) and `apiPercentUsed` bucket breakdowns when returned.
- **Refresh** — in-memory only for the app session; rotated refresh tokens are cached in `CursorUsageProvider`. Concurrent refreshes use a bounded handoff keyed by the detected source-token identity and its generation. This lets a late caller reuse a completed rotation, but prevents a new or restored account source from using an old result. Open Cursor if refresh fails.
- **UX** — `cursorError` surfaces in popover/settings/diagnostics. Its total and expanded breakdown bars honor the shared `left`/`used` progression setting while severity always receives percent used. Cursor is secondary-only and never drives the selected Claude/Codex menu-bar dot/number/error, widget, or quota notifications.
